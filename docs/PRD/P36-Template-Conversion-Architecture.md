# P36 Template Conversion Architecture

> 任务性质：架构确认文档
> 
> 本文只定义未来的模板页转换规则，不修改任何代码，不提交，不推送。

## 1. 当前问题

当前 Showcase Engine 已经从“行业导向”升级到“模板获客导向”，但页面结构里仍保留了过多中部信息区，导致模板详情页承担了太多任务。

现状问题不是视觉风格，而是信息职责混杂：

- 模板页既在展示成品模板，也在承担项目介绍
- “项目资料 / 交付 / 价格 / 联系方式 / 开始提交资料”被放在内容中部，打断了模板成品展示节奏
- 手机端主视觉与 CTA 的关系不够清晰
- 桌面端缺少一个稳定的“咨询卡片”承接转化信息

结论：

模板页应该回到单一职责，成为“成品模板展示页”，把成交动作收纳到统一的 `Project Starter CTA` 模块中。

## 2. 新两层结构

最终简化为两层：

1. `Home` 首页
2. `Template` 模板页

结构示意：

```text
Home
↓
Template
```

原则：

- 首页负责分发模板入口
- 模板页负责展示成品效果
- 转化动作统一由 CTA 模块完成
- 不再让中部正文同时承担展示和成交

## 3. 必须保留的功能

以下功能必须保留，不允许删除：

- 项目资料
- Logo / 图片 / 公司名称 / 联系方式 / 业务介绍
- 开始提交资料
- 交付周期 3-5 天
- 价格 / 获取报价
- WhatsApp 导流预留
- Email 导流预留
- 中英文兼容

这些功能不是要移除，而是要重新分配到更合理的展示区域。

## 4. 只是移动位置的功能

以下内容不删除，只移动位置或重组层级：

- 项目资料：从详情页中部移动到 `Project Starter CTA`
- 交付周期 3-5 天：移动到 CTA 模块的辅助信息区
- 价格 / 获取报价：移动到 CTA 模块，不做复杂报价系统
- 开始提交资料：变成 CTA 主按钮
- WhatsApp / Email：变成 CTA 的导流按钮或固定联系入口
- 中英文切换：继续保留，但不再干扰模板主内容结构

## 5. Project Starter CTA 模块设计

`Project Starter CTA` 是未来模板页的统一转化模块。

它的职责：

- 收集项目启动前最重要的信息
- 提醒客户准备资料
- 提供初步报价入口
- 提供 WhatsApp / Email 快速联系

建议模块内容：

- 标题：`Start Your Project`
- 说明：这是准备资料、确认需求、获取报价的入口
- 信息项：
  - Logo
  - 图片
  - 公司名称
  - 联系方式
  - 业务介绍
  - 交付周期 3-5 天
- 行动按钮：
  - `开始提交资料`
  - `获取报价`
  - `WhatsApp`
  - `Email`

模块可以有三种承载形态：

1. 模板页底部完整区块
2. 桌面端右侧 sticky 咨询卡片
3. 手机端底部固定按钮 + 展开式资料区

## 6. 桌面端布局建议

桌面端建议保持当前模板展示风格不变，只调整转化结构。

建议：

- 模板页主体只负责展示成品模板
- 页面右侧增加 sticky `Project Starter CTA` 卡片
- 主体内容与 CTA 在视觉上分离
- CTA 卡片只包含最必要的信息
- 不要让报价、资料、联系方式散落在正文中间

推荐布局：

```text
[Template Visual Main]
[Template Visual Content]
[Project Starter CTA - sticky right sidebar]
```

桌面端 CTA 应显示：

- 项目资料入口
- 交付周期 3-5 天
- 获取报价按钮
- WhatsApp / Email

## 7. 手机端布局建议

手机端优先考虑易理解、低干扰、强转化。

建议：

- 模板页主体先完整展示成品模板
- 底部放一个固定 CTA 按钮区
- 点击 CTA 后展开资料区
- 不要让长表单或多字段信息占据首屏

推荐布局：

```text
[Template Visual Main]
[Template Content]
[Bottom CTA Button]
[Expandable Project Starter Panel]
```

手机端 CTA 行为：

- 默认只显示一个主按钮：`开始提交资料`
- 可展开第二层：项目资料 / 交付 / 报价 / 联系方式
- WhatsApp 和 Email 作为快速转化入口

## 8. 获取报价功能的最小实现方案

当前阶段不要做复杂报价系统，只保留最小闭环。

最小实现：

- `获取报价` 按钮
- `WhatsApp` 链接
- `Email` mailto 链接
- 后续表单入口占位

推荐实现方式：

- 报价按钮先跳转到现有咨询流程或 Brief 页面
- WhatsApp / Email 使用统一配置，不写死在多个文件里
- 如果将来要做表单，预留 `Quote / Brief / Contact` 入口

不建议现在做：

- 自动报价引擎
- 复杂价格计算器
- 登录态报价系统
- 数据库驱动报价状态

## 9. 不允许删除的现有功能清单

以下功能必须保留：

- 模板详情页成品展示
- 首页模板入口
- 中英文切换
- 项目资料相关信息
- 交付周期说明
- 获取报价入口
- WhatsApp 导流
- Email 导流
- 已有视觉风格
- 已有模板图片资源

以下内容可以改位置，但不能删除：

- 开始提交资料
- 价格信息
- 公司名称
- Logo
- 联系方式
- 业务介绍

## 10. 后续真正改代码时的执行步骤

后续进入代码修改时，必须按以下顺序执行：

1. 先确认模板页当前路由与组件归属
2. 先抽出 `Project Starter CTA` 的数据结构
3. 再调整模板页布局层次
4. 再调整手机端与桌面端 CTA 承载位置
5. 再接入 WhatsApp / Email 配置
6. 再检查 build
7. 再检查线上部署
8. 最后才考虑进一步简化中部信息区

执行纪律：

- 不先改视觉
- 不先加新功能
- 不先扩 SEO Matrix
- 不先改模板池结构
- 不先碰首页滚动逻辑
